# Common project files and explicit OpenAI fallback

Use fictional files and a disposable account. Never use a real provider call for automated tests.

- Upload ZIPs or individual PPTX/PPT, DOCX/DOC, PDF, RTF/ODT, XLSX/XLS/CSV/TSV, code, notebooks, PNG/JPG/WebP/GIF/BMP/TIFF. The existing 10 MB individual-file and 32 MB upload limits apply. The ZIP container and excluded files are not retained.
- PPTX text and speaker notes follow presentation slide order. PDFs use native text and local OCR for pages with little text. Images use local OCR. A failed OCR result must keep the original selectable, with reading notes rather than silently excluding it. GIF/TIFF and other multiframe images use only the first frame; upload additional frames separately.
- PPTX embedded visuals, DOCX embedded images, scanned PDFs and images retain account-owned original files. Legacy Office, RTF, ODT and Excel files defer text reading to OpenAI. Non-PDF file input reads text; export those formats to PDF when visual charts are important. Ordinary text-based PDFs/DOCX retain their existing local text workflow.
- Preparing files, changing selections, estimates, reopening materials, downloading originals and restoring backups never invoke OpenAI. The explicit Analyze action includes selected excerpts and originals flagged for review in a single request, using the selected model. There are no automatic paid retries. Modern Office visuals render to PDF locally before the request; failed conversion shows an actionable error and makes no provider call.
- Inspect the picker and saved snapshot: reading notes, preview truncation and original-download links must stay visible. The estimate includes a planning allowance for original files; actual file/visual token usage varies. Limits are 8 originals, 120 pages/slides and 32 MB attachments per analysis; project presentations/PDFs allow 100 slides/pages each. DOCX keeps its 30-page import limit.
- A visual/file finding must be marked as an AI interpretation to check against the original, with page and download link when available. It cannot pretend to have locally verified text line numbers. Exact local-text findings still require an exact source quote. Unreadable-placeholder text is not evidence. Findings describe project contents and do not establish applicant authorship, execution or achievements.
- Another account cannot download or analyze the original. Missing or changed originals must stop preparation before a provider call. Export/import must retain original bytes and remap all nested references; missing originals or forged hashes must reject the backup before any records are written. Account cleanup removes project originals with their dependent upload records. These files cannot be imported as resumes.

Verify desktop and narrow-screen geometry, reopening after reload, mixed uploads plus GitHub links, and the normal top progress bar throughout preparation and the provider request. Do not replace a live deployment while a user task is running.

## Response budgets and settings

Project analysis requests compact findings with 32,000 response tokens automatically, or 64,000 for more than eight files, more than 20 visual pages/slides, or extra-high/maximum reasoning. Settings → AI setup provides Automatic or a saved account response limit from 1 to 128,000 tokens. The selected limit includes reasoning and formatting tokens; input tokens are billed separately. Project estimates show the effective limit. The preference is included in account backups and affects only future calls. It does not change the model or reasoning level. Connection tests and Application Assistant retain their smaller budgets; image generation and audio use separate limits.

Simulate an incomplete provider response: exactly one POST, recorded incomplete usage and effective limit, no replacement of earlier analysis, and no automatic retry. Simulate a temporary provider failure and verify the same no-retry behavior. Work Styles autosaves and free estimate POSTs must not create global processing entries; their screen retains save/error feedback while real provider tasks stay visible.

Selected files are shown as one list of file cards. Visual-review notes, reading notes and the original download belong inside their file card; they do not represent a separate analysis. A failed/interrupted attempt with no successful findings offers Retry analysis with OpenAI. Opening that card only opens materials and never starts the paid call. Previous successful findings remain viewable after a later failure. Historical output-limit messages describe the previous attempt and point to the current allowance.
