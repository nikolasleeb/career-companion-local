# Classes, project editing, and website materials

Class management lives on each education card. Add class offers manual names or the existing local PDF/DOCX/TXT transcript parser (10 MB, 30 pages). Review and select parsed names; additions append without replacing existing classes. Duplicate names and existing aliases are skipped. Course IDs, statuses, syllabus documents, details, and project references remain intact. The transcript itself is not stored and parsing makes no AI request.

`POST /api/profile-courses/{parent}/add` accepts `expected_updated_at` and `titles`. The save is atomic, account scoped, limited to education parents, and returns a conflict when the parent changes. The dialog retains names and selections and can refresh the expected version without clearing them. Profile class APIs remain available during setup; readiness rules and global counts are unchanged.

Project overview uses a single bullet-enabled text field, with a separate contribution field. Existing accomplishments keep their statement type internally. Exact matches, reordering, and unambiguous one-to-one edits preserve statement IDs and assignments. Ambiguous splits, merges, or simultaneous rewrites and insertions await assignment. A separate assignment dialog manages whole-project and stage scopes. Connection management retains explicit detach resolutions for statements and details. Current-parent stages appear first; other stages collapse. Stage dates use date controls; In progress stores `Present` and restores the previous draft end date when unchecked.

Master exports share one snapshot. Course names use regular text; their reviewed personal details use bold, nested bullets with hanging indents. Course statuses and syllabus content are omitted from both formats without changing stored data. Job/project details retain their existing weight, hierarchy, dates, and links.

Project materials has a versioned Save links operation independent of importing or analysis: `PUT /api/experience/{id}/project-links`. It only changes project link fields. Public website discovery uses `POST /api/project-sources/website` with `urls` and optional `experience_id`; it reads supplied pages and lists discoverable same-site pages and linked supported documents. Google Sites discovery is restricted to the particular `/view/{site}` or `/site/{site}` path. It never crawls the listed pages automatically.

`POST /api/project-sources/{id}/website-preview` reads selected candidate paths into a new source revision. Selection uses the existing `/select` endpoint and immutable snapshots. Preview and save make no AI request. Analyze with OpenAI is explicit, retains the existing estimate/review/approval workflow, and stays disabled with an explanation if no readable material is selected. Source text is not personal evidence until reviewed.

Every fetched page, document, and redirect uses the existing public network guard, which rejects credentials, local/private addresses, unsupported ports, and DNS rebinding. Imports use no ambient cookies or credentials. Limits remain 30 selected items, 200 KB extracted text per item, and 2 MB total; each download is bounded to 10 MB. Failed loads retain prior material and selections. Unavailable/login pages can be saved as references, with file upload and paste alternatives. Website references are validated on backup/import and entity references use the existing remapping path.
