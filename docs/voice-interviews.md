# Recorded interview practice

Interview Practice retains its written workflow. Each question also offers Typed,
Voice and Mixed answers, plus explicit paid question narration. A voice turn is
recorded first, then sent for transcription and delivery observations. Review and
correct the transcript before requesting answer feedback. Mixed mode appends typed
notes or code; code is never executed.

Microphone access starts only after Start recording. Hiding the tab or leaving the
question stops and discards an active recording. Limits are five minutes and
20 MB; the browser converts recordings to mono 24 kHz PCM WAV. The app does not
persist recordings in files, databases, backups, task inputs, logs or caches.
Audio is sent to the account's AI provider under that provider's retention terms.
Narrated questions have a three-minute server-memory playback buffer and a
browser-memory playback URL, removed when the question is closed.

The fixed audio models are gpt-transcribe, gpt-audio-1.5 and
gpt-realtime-2.1-mini. Text feedback uses the saved AI setup. No substitute model
or automatic paid retry is used. A recording permits one transcription and one
delivery request. Feedback and narration are separately requested and priced.
Unsupported models, missing usage details and incomplete calls are visible; an
unknown charge is not recorded as zero. Check saved audio status after a lost
connection. Recovery never resends a recording automatically; after a server
restart, audio cannot be recovered, but completed text remains available.

Pace and approximate pauses describe the original recording. The existing audio
delivery request also estimates audible um/uh/erm/er/hmm occurrences, including
prolonged sounds; one continuous sound counts once. This is an AI estimate, not
an exact acoustic measurement. Missing or invalid estimates remain unavailable,
never zero. The original transcript's filler-token count is separate: transcription
can omit fillers, even when they are audible. Longer spellings such as ummm and
uhhh are recognized when present in text. Transcription prompts explicitly request
verbatim fillers, as supported by the [OpenAI transcription guidance](https://developers.openai.com/api/docs/guides/speech-to-text#prompting).
Older saved recordings retain their results without fabricated estimates or paid
reprocessing; their temporary audio is no longer available. AI delivery comments are qualitative observations, not personality,
emotion, health, honesty, accent-quality or hiring assessments. Transcript edits
do not change the original measurements. Reviewed Profile examples carry source
snapshots and dates. Optional Work Styles context requires both account consent
and a per-session switch and includes only the approved paragraph. Imported
sessions start with that switch off.

Create practice material makes an illustrative, read-only slide, code sample or
case on request. Review useful details presents tentative quoted answer claims;
users edit, link and individually approve each before it enters Supporting
Details. Deleting practice keeps explicitly approved Profile details with detached
source provenance. No resume or application is automatically rewritten.

## Verification

Tests use fictional accounts and mocked providers. The browser check uses a
synthetic microphone; it does not send paid requests. Real provider availability
and subjective voice quality require an explicit paid action by an account user.

The usage API accepts day, week and month. Weeks begin Monday in the selected
time zone; filtering happens before aggregation. Chart labels adapt to width and
an accessible table retains exact bucket dates, amounts and unknown-charge flags.
